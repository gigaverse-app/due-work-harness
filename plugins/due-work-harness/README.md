# pytest-obligation plugin

This plugin teaches Codex and Claude Code to use [pytest-obligation](https://github.com/gigaverse-app/pytest-obligation) in Python repositories. Its primary job is to bind an application's real workflow to a `DueWorkContract`, which generates standardized pytest cases for the current A–J guarantee catalog, including recovery, crash ambiguity, convergence, gated execution, harmless replay, indivisible admission, and retry limits. The coding agent can also use the harness's fault-injection infrastructure to write focused tests for risks particular to that application. The plugin contains two skills and no MCP server. The pytest library is installed separately in the project under test.

- [`prove-due-work`](skills/prove-due-work/SKILL.md) adopts the published harness in a project and reports what its generated tests actually prove.
- [`probe-upstream-due-work`](skills/probe-upstream-due-work/SKILL.md) investigates an external open-source project, independently reproduces a finding, and prepares an upstream disclosure when requested. It uses this repository's existing [upstream playbook](https://github.com/gigaverse-app/pytest-obligation/blob/main/docs/upstream-playbook.md) rather than duplicating it in the plugin.

Use it when a Celery task goes missing, a queue worker repeats a job, a Django transaction commits but the follow-up message is not published, or a Kafka consumer crashes between processing and committing its offset. It also helps test whether retries double-charge a customer, resend a receipt, or leave a Shopify order, notification, data import, or external API effect unfinished. The core accepts plain Python callables, without assuming a framework or business domain. Optional adapters cover particular boundaries in Django/PostgreSQL, django-tasks, Celery, RQ/Redis, MongoDB, Prefect, and aiokafka. Shopify can be tested through a real application seam; there is no released Shopify-specific adapter. The skill names the limits of each integration.

In Claude Code, add the repository as a marketplace, then install `pytest-obligation@pytest-obligation`. In Codex, install the package from the shared plugin directory once published, or load this plugin directory locally while developing it. Ask to prove your own workflow or to investigate an external project's due-work bug; the skills have separate scopes.

The `gigaverse-backend` repository has its own [due-work skill](https://github.com/gigaverse-app/gigaverse-backend/blob/main/.agents/skills/due-work/SKILL.md) and internal conformance harness. Use its local runtime and test policy there, even though both harnesses now describe A–J guarantees. The public package's current `main` has A–J; PyPI `v0.7.0` predates that migration, so check the installed package and its matching adoption guide before writing a contract.

The skill's instructions can be read in a chat, but executing proofs requires a coding environment with the target repository, Python, and the services used by its tests. See the [adoption guide](https://github.com/gigaverse-app/pytest-obligation/blob/main/ADOPTING.md) for the package setup and contract requirements.
